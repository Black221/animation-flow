Plan d'implémentation du moteur

Ce plan fait passer le moteur actuel (des clés interpolées, des poses en boucle, cinq types de primitives) à un moteur de dessin animé et de motion design complet. C'est le niveau cumulé de Spine ou Moho pour les personnages et d'After Effects ou Lottie pour le motion design. Tout reste décrit en données, déterministe et vérifiable par des mesures. Chaque lot indique les fichiers touchés, l'algorithme retenu, les tests et le critère d'acceptation.

Le fonctionnement actuel du moteur et la liste des améliorations sont sur la page Moteur animation-flow.

Les durées sont estimées pour un développeur confirmé. Avec des sessions Claude, le code va plus vite, mais la relecture des images et des mesures prend le même temps : c'est elle qui fixe le rythme.

Calendrier et équipes

Quatre équipes avancent en parallèle : moteur, styles et rendu, IA, éditeur. La phase 1 passe avant la fluidité parce qu'elle fournit les mesures qui jugent tout le reste. Les jalons en rose sont des démonstrations sur le banc d'essai.

Les règles à ne jamais casser

Une image ne dépend que du projet et de t

Aucun Math.random, aucune horloge. Le hasard est semé par l'identifiant de l'élément. Ce qui a un état (ressorts, cordes) se calcule à pas fixe depuis le début de la scène, avec des points de reprise, pour que les morceaux rendus en parallèle se recollent sans raccord.

Des données, jamais du code

Le modèle d'IA et l'utilisateur écrivent du JSON validé. La liberté du code passe par des formules dans un petit langage sûr : pas de boucle, pas d'accès au système, un budget d'évaluation.

Rien ne change pour un projet existant

Format v2 avec une migration automatique depuis la v1, et chaque champ nouveau est facultatif. Test de garde : les modèles de projets et le projet d'exemple donnent les mêmes images, au pixel près, avant et après chaque lot.

Le moteur dit quoi et où, le style dit comment

Formes, masques, effets et fusion sont décrits par le moteur dans la Frame, puis appliqués par un compositeur commun aux styles. Chaque ajout doit marcher dans les six styles, ou déclarer qu'il ne s'applique pas à l'un d'eux (par exemple le flou dans le papier découpé).

Le temps suit la voix, et la musique

Une clé peut viser une réplique, et désormais aussi un temps de la musique ({ beat: 17 }). Actions et intentions s'ancrent de la même façon.

Tout se mesure

Une fonction qu'on ne peut pas vérifier ne sort pas. Chaque lot livre ses critères dans measure.ts et ses tests dorés (images de référence).

Architecture cible : le calcul d'une image

frameAt(t) passe de 5 à 12 étapes. L'ordre compte : les contraintes s'appliquent après les poses, le mouvement secondaire réagit au mouvement final, et la déformation vient avant les opérations sur les formes. Le résultat n'est plus une liste plate de primitives, mais un petit arbre de composition (groupes avec masque, fusion et effets), que le compositeur commun aplatit pour le style.

Le format v2, en résumé

Tout est facultatif. Un projet v1 migré ne contient aucun de ces champs et se comporte comme avant. Les noms suivent le vocabulaire du motion design (After Effects, Lottie) pour que les modèles d'IA les reconnaissent.

// packages/schema — ce qui s'ajoute (extrait)
schemaVersion: 2
// temps : une réplique, ou un temps de la musique
TimeRef = number | { line, edge, offset } | { beat, offset }
// clé : interpolation temporelle et spatiale
ElementKey += {
  ease: 'inOut' | … | { bezier: [x1, y1, x2, y2] } | { spring: { stiffness, damping, mass } },
  path: 'auto' | 'linear' | { in: [dx, dy], out: [dx, dy] },   // tangentes spatiales
  sx, sy, skew, z, rotX, rotY, anchorX, anchorY,
  action, actionSpeed, blend, layers: [{ pose, parts, weight }],
  view, lookAt, expressionTransition: 'cut' | 'take',
}
Element += {
  type: 'character' | 'prop' | 'text' | 'shape' | 'comp' | 'particles' | 'chart' | 'null',
  parent: { element, part? },              // attache : suit la main droite de…
  constraints: [{ ik: { chain, target } } | { lookAt } | { plant: 'feet' }],
  mask: { shape | element, mode: 'alpha' | 'luma', invert, feather },
  blend: 'multiply' | 'screen' | 'overlay' | …,
  effects: [{ blur } | { shadow } | { glow } | { levels } | { lut } | { noise } | …],
  motionBlur: { shutter: 180 },
  expr: { "x": "wiggle(2, 12)", "rotation": "valueAt('roue', t) * 0.5" },
  formats: { "9:16": { x, y, scale } },        // retouche par format
}
Asset += {
  rig: 'humanoid' | 'quadruped' | 'custom',   // noms de parties standard → actions réutilisables
  views: { front, q34, side, back },
  actions: { throw: { duration, loop, tracks: { arm_r: [{ t, rot, sx, sy, ease }] } } },
  bones, skin,                          // déformation par os
  springs: { tail: { stiffness, damping, gravity } },
  visemes: { rest, A, E, O, MBP, FV, L },
}
Project += {
  comps: { id: { width, height, duration, elements } },
  variables: { titre: { type: 'text', value } }, data: { ventes: [[…]] },
  brand: { fonts, colors, logos },
  fps: 24 | 25 | 30 | 50 | 60,
}

PHASE 0

Fondations

3 semainesmoteur, styles≈ 5 semaines-dév.

Préparer le terrain sans rien changer à l'image : format v2, pistes de valeurs, arbre de composition et outils de test. Tout le reste s'y appuie.

0.1Format v2 et migration

  • SCHEMA_VERSION 2, migrateProject() qui accepte v1 et renvoie v2. Appliqué à la lecture en base, à l'import d'un fichier et dans la génération.
  • Les schémas JSON envoyés au modèle ne montrent que les champs utiles à l'étape en cours, pour ne pas le noyer.
packages/schema/src/index.ts, apps/api (lecture des projets), migration SQL sans changement de colonnes

0.2Pistes de valeurs

  • Refonte interne : les clés d'un élément deviennent une piste par propriété (x, y, échelle…), précalculée une fois par scène dans l'évaluateur (temps résolus, tangentes).
  • L'échantillonnage passe d'un parcours linéaire à une recherche dichotomique : O(log n) par valeur.
packages/engine/src/animate.ts, nouveau tracks.ts

0.3Arbre de composition et compositeur commun

  • Nouvelle primitive group (enfants, opacité, fusion, masque, effets) dans la Frame.
  • Un compositeur commun (styles/src/composite.ts) rend chaque groupe dans un canevas hors écran quand il le faut (masque, effet, fusion), sinon directement.
  • Réserve de canevas réutilisés, pour éviter l'allocation à chaque image.
packages/engine/src/primitives.ts, packages/styles/src/common.ts, composite.ts

0.4Mesures de texte dans le moteur

  • Les métriques des 4 polices livrées (avances, crénage, ascendante) sont extraites des TTF au build (opentype.js) dans fonts-metrics.json.
  • La mise en page du texte devient identique au navigateur et à Node, et le moteur connaît la boîte de chaque lettre : c'est indispensable pour les animateurs de texte et les mesures.
packages/engine/src/text-layout.ts, scripts de build

0.5Bancs de test

  • Tests dorés : images de référence par style, comparées avec une tolérance (1 % de pixels, écart moyen ≤ 2/255), dans Node et dans Chromium.
  • Déterminisme : l'empreinte de 20 images doit être identique en 1 et en 4 morceaux.
  • Performance : ms par image mesurées en intégration continue sur le banc d'essai.
packages/styles/test, packages/render/test, nouveau bench/

Accepté quand

  • Les 3 modèles de projets et le projet d'exemple donnent les mêmes images, au pixel près, qu'en v1.
  • Tous les tests existants passent, et les tests dorés et de déterminisme tournent en intégration continue.
PHASE 1

Voir et mesurer

3 semainesIA, moteur, éditeur≈ 7 semaines-dév.jalon J1

Le modèle d'IA regarde enfin les scènes en mouvement, et chaque film reçoit un rapport chiffré. C'est l'équivalent des planches, rubans et check-motion du film Maelia, intégrés à la plateforme.

1.1measure.ts

  • Échantillonnage de chaque scène à 12 images/s (24 pour les à-coups).
  • Critères :
    • à-coups au-delà de 60 px ou 0,7 rad par image ;
    • glissement des pieds ;
    • bande des sous-titres ;
    • temps de lecture des textes (0,3 s + 1 s par 15 caractères) ;
    • personnage qui parle hors cadre ou caché ;
    • chevauchement de textes ;
    • plan immobile plus de 4 s ;
    • plus de 2 mouvements majeurs en même temps ;
    • flashs (au plus 3 par seconde, règle d'accessibilité contre l'épilepsie photosensible).
  • Chaque écart est un Issue avec son chemin (scenes.2.elements.1.keys.3), son image, sa gravité et un conseil de correction.
nouveau packages/engine/src/measure.ts

1.2Contraste mesuré sur l'image rendue

  • Rendu en style plat, puis couleur du fond échantillonnée sous la boîte de chaque texte.
  • Rapport de contraste WCAG : 4,5:1 au moins, 3:1 pour les titres de plus de 48 px.
packages/render/src/still.ts, measure-render.ts

1.3Planche, ruban et gros plan

  • Planche : 8 à 12 images d'une scène avec leur temps.
  • Ruban : chaque image d'un geste repéré par les mesures ou par l'action principale.
  • Gros plan sur le visage de celui qui parle.
  • Les images sont réduites (1024 px de large au plus) pour limiter le coût du modèle qui voit.
packages/ai/src/preview.ts, packages/render/src/still.ts

1.4Relecture du mouvement et correctifs ciblés

  • Nouvelle étape motion dans la génération : le modèle reçoit la planche, le ruban, les mesures et la liste de contrôle du guide.
  • Réponse : { ok, problems, patch }, où patch est un sous-ensemble de JSON Patch (RFC 6902) limité aux clés, aux actions et aux paramètres de la scène.
  • Boucle de 3 tours au plus, qui s'arrête quand les mesures passent et que la relecture dit bon.
packages/ai/src/pipeline.ts, prompts.ts, nouveau patch.ts

1.5Rapport de génération

  • generation.report : critères contrôlés (valeur, seuil, statut), non contrôlés (jeu de la voix, humour) et défauts connus.
  • Affiché sur la page de la génération et gardé avec le projet.
apps/api/src/routes/generations.ts, apps/web/src/pages/Generate.tsx

1.6Panneau des mesures dans l'éditeur

  • La liste des écarts de la scène ; un clic amène à l'image concernée et sélectionne l'élément.
  • Mesures recalculées à la sauvegarde.
apps/web/src/components/MeasuresPanel.tsx

1.7Gains rapides : flou de mouvement et 60 i/s

  • Flou de mouvement : obturateur de 180° par défaut ; 3 à 8 sous-instants, selon la vitesse maximale dans l'image (pas de sous-instant si rien ne bouge de plus de 8 px par image) ; accumulation dans un tampon en virgule flottante pour éviter les bandes.
  • Cadences : ajout de 50 et 60 images/s.
packages/styles/src/output.ts, packages/render, schema (fps)

Accepté quand

  • Sur le banc d'essai, le nombre d'écarts mesurés baisse d'au moins 70 % entre le premier jet et la fin de la boucle.
  • Chaque génération affiche son rapport.
  • Le flou de mouvement ne coûte rien sur une image fixe.
PHASE 2

Fluidité

3 à 4 semainesmoteur, éditeur≈ 8 semaines-dév.

Supprimer les saccades : les mouvements ne s'arrêtent plus à chaque clé, les poses se fondent, et tout peut suivre une formule.

2.1Bézier temporel

  • Accélération par courbe de Bézier cubique, comme en CSS ou avec l'influence et la vitesse d'After Effects. Les préréglages actuels deviennent des courbes nommées.
  • Résolution de x(u) = s par Newton, avec repli par dichotomie : précision de 1e-6, sans allocation.
packages/engine/src/math.ts, tracks.ts

2.2Trajectoires spatiales

  • Chemin par défaut : Catmull-Rom centripète (α = 0,5, sans boucle ni rebroussement) avec tangentes automatiques. Poignées explicites possibles.
  • Clés « itinérantes » : vitesse constante le long du chemin, par reparamétrage à l'abscisse curviligne (table de 64 échantillons).
  • Orientation automatique selon la tangente (un avion, une flèche).
packages/engine/src/tracks.ts, geometry.ts

2.3Ressorts analytiques

  • Interpolation spring par la solution exacte de l'oscillateur amorti (sous-amorti, critique ou sur-amorti), sans simulation.
  • La vitesse héritée de la clé précédente préserve la continuité. Préréglages « doux », « vif », « rebond ».
packages/engine/src/math.ts

2.4Fondu entre poses, couches, accord des phases

  • Fondu : de 0,2 à 0,4 s par défaut, en interpolant les angles par le plus court chemin.
  • Couches : chaque couche vise un groupe de parties (haut du corps, bas du corps, ou une liste) avec un poids.
  • Accord des phases : en passant de marche à course, la phase du cycle est conservée, pour que les pieds ne sautent pas.
packages/engine/src/assets.ts, nouveau rig.ts

2.5Formules sûres

  • Analyseur de Pratt écrit à la main, qui produit un arbre de syntaxe. 200 nœuds et une profondeur de 16 au plus.
  • Fonctions permises : sin cos abs min max clamp lerp smooth, noise(t, seed), wiggle(freq, amp), spring, loopOut('cycle' | 'pingpong'), valueAt(élément, t), time, index, beat, amp, var('nom').
  • Aucune boucle, aucune affectation. Toute erreur est signalée au modèle avec sa position.
nouveau packages/engine/src/expr.ts

2.6Remappage du temps

  • Ralenti, accéléré, arrêt sur image, boucle et aller-retour, pour un élément ou une composition (voir 5.8).
  • Une piste time est elle-même animable (effet « bullet time »).
packages/engine/src/timing.ts

2.7Éditeur de courbes et trajectoires à l'écran

  • Graphe de valeur et de vitesse par propriété, avec des poignées de Bézier.
  • Trajectoire dessinée sur la scène, avec des poignées déplaçables. Pelures d'oignon à ± 3 images.
apps/web/src/components/GraphEditor.tsx, Stage

Accepté quand

  • Tests de propriétés : avec les tangentes automatiques, la vitesse est continue à chaque clé intérieure (écart ≤ 1 %).
  • Un changement de pose ne fait pas tourner une partie de plus de 0,1 rad d'une image à l'autre.
  • Le ressort critique atteint sa cible à ± 0,5 px sans la dépasser.
  • Aucun à-coup mesuré sur les films 1, 5 et 9 du banc d'essai.
PHASE 3

Personnages

6 semainesmoteur, IA, éditeur≈ 14 semaines-dév.jalon J2

Le niveau du film Maelia, écrit en données : gestes qui commencent et finissent, objets tenus, pieds plantés, vues multiples, visages vivants.

3.1Rig standard

  • Nomenclature humanoid : hips, torso, neck, head, arm_l/r, forearm_l/r, hand_l/r, leg_l/r, shin_l/r, foot_l/r, plus les groupes eyes et mouth. Même principe pour quadruped.
  • Vérification : la hiérarchie et les pivots sont contrôlés à la génération du dessin.
  • Réutilisation : c'est ce qui permet de rejouer une même action sur n'importe quel personnage, par retargeting avec mise à l'échelle des longueurs de membres.
packages/schema, packages/ai/src/drawing.ts (consignes et contrôle)

3.2Actions à clés et bibliothèque

  • Définition : une action est un ensemble de pistes par partie (angle, décalage, échelle), jouée une fois ou en boucle, avec une intensité de 0 à 2.
  • Bibliothèque de départ (≈ 40 actions humanoïdes) : marcher, courir, sauter avec anticipation, s'asseoir, se lever, lancer, attraper, pointer, applaudir, hausser les épaules, trébucher, danser (3 styles), saluer, se gratter la tête, taper du pied…
  • Chaque action a sa planche de contrôle.
nouveau packages/engine/src/rig.ts, packages/library/src/actions/

3.3Parentage entre éléments et attaches

  • parent: { element, part } : un objet suit la matrice d'une partie d'un autre élément, avec un décalage local. Les cycles de parentage sont refusés à la validation.
  • Changement de parent en cours de scène (attraper, puis lancer) sans saut : la position mondiale est conservée à l'instant du changement.
packages/engine/src/evaluate.ts, nouveau constraints.ts

3.4IK

  • Chaînes à 2 os (bras, jambes) : solution analytique par la loi des cosinus, avec le sens de pliure choisi (le coude va vers l'extérieur).
  • Chaînes plus longues (queue, tentacule) : FABRIK, en 10 itérations au plus.
  • Cibles : un point, un élément ou une partie d'élément. Mélange IK / cinématique directe par un poids animable.
packages/engine/src/constraints.ts

3.5Locomotion et pieds plantés

  • La phase du cycle se calcule à partir de la distance parcourue et de la longueur de foulée (déduite de la jambe) : la marche suit la vitesse réelle.
  • Pendant l'appui, l'IK de jambe verrouille le pied à sa position au sol. Les pentes suivent une ligne de sol décrite par le décor.
packages/engine/src/rig.ts, constraints.ts

3.6Mouvement secondaire

  • Ressorts angulaires sur les parties déclarées (tresse, queue, oreilles, chapeau, écharpe), excités par l'accélération réelle de leur parent.
  • Intégration semi-implicite à pas fixe (1/240 s), avec des points de reprise toutes les 0,5 s mis en cache : on accède à n'importe quel instant sans tout rejouer, et les morceaux restent identiques.
nouveau packages/engine/src/secondary.ts

3.7Déformation

  • Squash & stretch par partie, à volume constant (sy = 1/sx), plus un écrasement automatique à l'atterrissage, déduit de la vitesse verticale.
  • Membres souples (style « rubber hose ») : le bras devient une courbe de l'épaule à la main, en passant par le coude.
  • Peau sur os : poids calculés automatiquement par distance aux os, fusion linéaire des matrices.
packages/engine/src/assets.ts, nouveau deform.ts

3.8Vues multiples

  • Un dessin peut avoir des vues front, q34, side, back, qui partagent les noms de parties : poses et actions s'appliquent à toutes.
  • Se retourner passe par les vues intermédiaires, en 2 à 3 images chacune, avec un léger étirement de mouvement.
packages/schema, engine/src/assets.ts, ai/src/drawing.ts

3.9Transitions d'humeur

  • Mode take : plissement d'anticipation (0,1 s), changement d'expression sous le plissement, réaction avec dépassement, puis retour au calme (0,25 s). Les petites clés de tête et d'échelle sont générées automatiquement, comme actP dans Maelia.
packages/engine/src/rig.ts

3.10Visage vivant

  • V1, visèmes tirés de l'enveloppe de la voix (RMS sur 10 ms, 4 ouvertures de bouche).
  • V2, visèmes calés sur les phonèmes : règles graphème → visème du français, alignées sur les temps des mots (Whisper). Classes A E O MBP FV L repos.
  • Clignement automatique toutes les 2 à 6 s, tirage semé, double clignement une fois sur cinq.
  • Regard vers une cible, par décalage des pupilles.
packages/audio, engine/src/rig.ts

3.11Foules

  • Instances d'un même dessin avec variations semées : palette, échelle ± 10 %, décalage de phase, choix de pose. Le coût reste linéaire en nombre d'instances.
packages/engine, library

3.12Côté IA et éditeur

  • Les consignes de dessin imposent le rig standard. Chaque dessin produit une fiche (poses, expressions, vues) relue par le modèle qui voit.
  • L'éditeur ajoute un panneau de rig (parties, IK et cibles déplaçables à la souris), la bibliothèque d'actions avec aperçu, et les clés par partie dans la frise.
packages/ai/src/drawing.ts, apps/web

Accepté quand

  • Sur la scène de marche de test, le pied glisse de 4 px au plus pendant l'appui.
  • L'IK atteint une cible accessible à 1 px près.
  • Une action rejouée sur 3 personnages de proportions différentes reste lisible à la relecture.
  • Le film 3 du banc d'essai (dialogue à deux personnages) tient tous les critères.
  • Les morceaux restent identiques avec des ressorts.
PHASE 4

La méthode Maelia dans la génération

4 semaines, puis 3 pour les intentionsIA, API, éditeur≈ 9 semaines-dév.

Reprendre la démarche qui a fait la qualité du film Maelia : un contrat, la voix d'abord, une validation avant d'animer, une scène modèle, un vocabulaire de haut niveau.

4.1Brief-contrat

  • Après le storyboard, le modèle extrait les faits, noms propres, chiffres (avec leur format) et éléments à montrer, ainsi que le ton et la durée.
  • L'utilisateur valide ce contrat avec le storyboard. Les mesures de fidélité le comparent aux textes des scènes, puis aux répliques retranscrites par Whisper.
packages/ai/src/storyboard.ts, apps/api (stockage), audio (transcription)

4.2La voix d'abord

  • Les répliques sont enregistrées juste après la validation du storyboard, avant l'écriture des scènes. Le modèle écrit sur les vrais temps.
  • Sans fournisseur de voix, on garde les durées estimées, et c'est dit dans le rapport.
apps/api/src/routes/generations.ts, voices.ts

4.3Fiches et images de style, validées par l'utilisateur

  • Nouveau point d'arrêt (facultatif, activé par défaut) : fiches de chaque personnage, une image de style par décor avec les personnages, écoute de la voix, et la liste des décisions à prendre. L'utilisateur corrige par une instruction, comme pour le storyboard.
apps/web/src/pages/Generate.tsx, api

4.4Scène modèle

  • La scène 1 est écrite, mesurée et relue jusqu'à passer tous les critères, puis envoyée comme exemple complet pour l'écriture des autres scènes, en parallèle. La continuité (tailles, côtés, costumes) est vérifiée d'une scène à l'autre.
packages/ai/src/pipeline.ts

4.5Guide d'animation chiffré et exemples

  • Le guide est en consigne, avec des nombres : anticipation, limites par image, lectures, zones libres, chaque plan bouge.
  • Une bibliothèque d'exemples choisis par genre (explication, publicité, histoire, typographie animée, données) ; on ne montre au modèle que ceux du genre demandé.
packages/ai/src/prompts.ts, examples/

4.6Intentions compilées en clés

  • Vocabulaire :
    • mouvement : enter(from), exit(to), walkTo(x, speed), runTo, jump(height) ;
    • objets : throwTo(prop, cible), hold(prop, main) ;
    • jeu : lookAt, say(ligne), react(humeur) ;
    • caméra : frame(sujet, 'plan moyen', 'tiers gauche'), pushIn ;
    • texte : reveal(texte, style), countTo(n).
  • Compilation par le moteur, de façon déterministe, avec anticipation, arcs et durées tirés du guide.
  • Le modèle peut mélanger intentions et clés.
nouveau packages/engine/src/intents.ts, schema

4.7Le modèle interroge le moteur

  • Appel d'outils ajouté aux fournisseurs (OpenAI, Anthropic, Gemini, Mistral).
  • Outils :
    • positionOf(élément, partie, t) ;
    • boundsOf(élément, t) ;
    • cues(), les temps des répliques ;
    • actionsOf(dessin) ;
    • freeRegions(t), les zones libres pour poser un texte.
  • 8 appels au plus par scène.
packages/providers/src, packages/ai/src/tools.ts

Accepté quand

  • Sur le banc d'essai, 100 % des chiffres du brief sont respectés et aucun n'est ajouté.
  • La scène modèle passe tous les critères.
  • Les scènes suivantes ont 50 % d'écarts en moins au premier jet que sans scène modèle.
  • La relecture humaine juge la continuité bonne sur 11 films sur 12.
PHASE 5

Motion design

8 à 9 semainesmoteur, styles, IA, éditeur≈ 20 semaines-dév.jalon J3

Tout ce qu'un motion designer attend : calques de formes, typographie animée, masques, effets, fusion, 2,5D, compositions réutilisables, gabarits, données et musique qui pilotent l'animation.

5.1Calques de formes

  • Formes de base : élément shape avec rectangle arrondi, ellipse, étoile, polygone et chemin, tous animables.
  • Contours : pointillés, extrémités, jonctions, et épaisseur variable le long du tracé (contour effilé).
  • Remplissages : dégradés linéaires et radiaux animables.
nouveau packages/engine/src/shapes.ts, primitives.ts, styles

5.2Opérateurs de formes

  • Tracé progressif : début, fin et décalage, coupés à l'abscisse curviligne, calculés dans le moteur pour que tous les styles en profitent.
  • Répétiteur : copies avec transformation cumulée, dégradé d'opacité et décalage dans le temps.
  • Déformations : décalage de contour, onde, zigzag, torsion, arrondi des angles, gonflement.
  • Fusion booléenne (union, différence, intersection) par la bibliothèque polygon-clipping (licence MIT).
packages/engine/src/shapes.ts

5.3Morphing

  • Préparation : les deux formes sont rééchantillonnées au même nombre de points, par abscisse curviligne.
  • Alignement : on choisit le point de départ et le sens qui minimisent la distance entre les deux formes.
  • Formes à plusieurs sous-chemins : appariement par aire et par centre.
  • Raccord de forme entre deux plans : la dernière forme de A devient la première de B.
packages/engine/src/geometry.ts

5.4Typographie animée

  • Animateurs par glyphe, mot ou ligne, grâce aux métriques de 0.4.
  • Sélecteurs de plage : début, fin, décalage ; forme carrée, rampe, triangle ou douce ; ordre aléatoire semé.
  • Propriétés animées : position, échelle, rotation, opacité, flou, couleur, crénage.
  • Préréglages : machine à écrire, vague, rebond par lettre, glissement par ligne, flou vers net.
packages/library/src/text.ts, engine/src/text-layout.ts

5.5Texte sur chemin, compteurs, écriture manuscrite

  • Texte sur chemin : il suit une courbe ou un cercle, avec un décalage animable.
  • Compteurs : un formateur propre (espace fine insécable, virgule décimale) et non Intl, pour un résultat identique partout. Le défilement s'arrête net sur la valeur exacte.
  • Écriture manuscrite : tracé progressif sur une police à trait unique (Hershey, domaine public).
library/src/text.ts, polices

5.6Masques, caches, fusion

  • Masques : forme animée, avec contour adouci, expansion et inversion.
  • Caches alpha et luminance à partir d'un autre élément, rendus hors écran puis appliqués par destination-in.
  • Modes de fusion natifs du Canvas : produit, écran, incrustation, lumière tamisée, différence, teinte, luminosité…
  • Tous vérifiés en tests dorés dans Node et Chromium.
styles/src/composite.ts

5.7Effets

  • Flou et ombres : flou gaussien (3 flous en boîte successifs, rapides en CPU), ombre portée, lueur extérieure et intérieure.
  • Couleur : niveaux, teinte et saturation, teinte en deux couleurs, table de correspondance 3D (fichier .cube, interpolation trilinéaire).
  • Matière : grain et bruit, déplacement par turbulence (réservé au rendu GPU s'il coûte trop), aberration chromatique.
  • Paramètres animables. Chaque effet déclare son coût, et le budget par image est respecté.
styles/src/effects/

5.8Compositions imbriquées

  • project.comps et un élément comp : un bloc animé réutilisé, avec remappage du temps, boucle et décalage. Profondeur de 8 au plus, cycles refusés.
  • Les formes et les textes d'une composition figée sont mis en cache en image.
schema, engine/src/evaluate.ts

5.9Transitions

  • Recouvrement : la timeline permet à deux scènes de se chevaucher pendant la transition. frameAt évalue alors les deux scènes et les compose.
  • Bibliothèque : volet (linéaire, radial, horloge), iris en forme, poussée, glissement, zoom, panoramique filé (flou et décalage), pinceau (comme Maelia), coupure numérique, raccord de forme.
engine/src/timing.ts, evaluate.ts, styles

5.102,5D et caméra

  • Calques en profondeur : profondeur z, rotation en X et en Y de calques plats (points transformés en 3D puis projetés, correct pour des plans), tri par z.
  • Caméra : focale, parallaxe automatique, travelling compensé (effet Vertigo).
  • Profondeur de champ quantifiée en 3 niveaux de flou.
  • Ombres au sol par projection de la silhouette.
  • Préréglages de caméra : travelling avant et arrière, panoramique, plongée, orbite.
engine/src/evaluate.ts, animate.ts

5.11Gabarits, variables, charte

  • Variables typées (texte, couleur, image, nombre), liées aux paramètres.
  • Rendu par lots depuis un tableau (CSV) : cent versions d'une vidéo.
  • Charte de marque au niveau de l'espace (polices, couleurs, logos), imposée à la génération et vérifiée : couleurs hors charte signalées.
  • Retouche par format (formats) en plus du recadrage automatique.
schema, apps/api (lots, charte), ai/src/prompts.ts

5.12Données et musique

  • Élément chart : barres, lignes, secteurs, aires et cartes simples, à partir d'un tableau.
  • Animations de graphique : croissance, ligne tracée, étiquettes qui comptent jusqu'à la valeur exacte.
  • Musique : temps exposés dans la timeline ({ beat }), exacts pour la musique composée, estimés pour une musique jointe.
  • Formules audio : amp (amplitude) et beat dans les formules.
nouveau library/src/charts.ts, audio, engine

5.13Côté IA et éditeur

  • IA : les consignes de motion design (règles de mise en page, hiérarchie, rythme de lecture), avec des exemples par genre.
  • Éditeur :
    • outils rectangle, ellipse et plume ;
    • panneau des opérateurs ;
    • animateurs de texte avec préréglages ;
    • panneau des effets ;
    • masques dessinés à la plume ;
    • variables et rendu par lots.
ai/src/prompts.ts, apps/web

Accepté quand

  • Les films 4 (typographie animée), 6 (révélation de logo), 7 (données) et 10 (clip de paroles) du banc d'essai tiennent tous les critères.
  • Les effets restent dans le budget par image.
  • Les tests dorés de fusion et de masques sont identiques dans Node et Chromium, à la tolérance près.
PHASE 6

Simulation, sorties, éditeur

9 semainesmoteur, rendu, éditeur≈ 9 semaines-dév.jalon J4

6.1Particules sans état

  • Principe : l'état d'une particule est une fonction pure de son âge, jamais un résultat de simulation.
  • Naissance : l'instant i/débit, avec des paramètres semés.
  • Mouvement : balistique avec traînée, en solution exacte ; turbulence par un bruit de curl échantillonné selon l'âge.
  • Émetteurs : point, ligne, rectangle, cercle ou chemin ; flux continu ou salve.
  • Évolution sur la vie : taille, couleur, opacité, rotation.
  • Apparence : forme, dessin ou glyphe. Rebond sur le sol.
  • Coût proportionnel au nombre de particules vivantes, sans aucun état à garder.
nouveau packages/engine/src/particles.ts

6.2Cordes et tissus simples

  • Verlet à pas fixe avec contraintes de distance, pour les écharpes, drapeaux et câbles. Points de reprise, comme en 3.6.
packages/engine/src/secondary.ts

6.3Rendu GPU

  • Base : un moteur de rendu WebGL2 pour le style plat d'abord. Les chemins sont triangulés (earcut) et les effets passent en shaders.
  • Aperçu : utilisé en temps réel dans l'éditeur.
  • Serveur : en option, par WebGL logiciel (SwiftShader, comme Maelia) ou sur une machine avec GPU.
  • Les tests dorés comparent le rendu GPU au rendu Canvas.
nouveau packages/styles/src/gpu/

6.4Exports

  • Lottie (pour le web et les applications) : sous-ensemble vectoriel en style plat, avec formes, clés, masques et textes. La relecture compare le rendu de lottie-web au nôtre.
  • Vidéo avec transparence : WebM VP9 yuva420p, ProRes 4444.
  • Autres : séquence PNG, pistes audio séparées (voix, musique, bruitages).
nouveau render/src/lottie.ts, render/src/ffmpeg.ts

6.5Plusieurs langues

  • Traduction des répliques et des textes par le modèle, avec le brief-contrat préservé (chiffres, noms), voix par langue et timeline recalculée.
  • Les textes à l'écran sont remis en page (écriture de droite à gauche comprise).
ai, audio, engine/src/text-layout.ts

6.6Performance

  • Cache par élément : quand ses primitives ne changent pas d'une image à l'autre (empreinte identique), son image est réutilisée.
  • Aperçus à mi-résolution pendant qu'on fait défiler la frise. Profilage par étape de frameAt affiché dans l'éditeur.
styles, apps/web

Accepté quand

  • 10 000 particules restent sous 50 ms par image en style plat.
  • Un export Lottie se superpose au rendu d'origine à 1 px près.
  • L'aperçu GPU tient 60 images/s sur les films 4 et 6 du banc d'essai.

Stratégie de tests

Unitaires et propriétés

Chaque algorithme a des valeurs de référence : Bézier, ressort, IK, morphing, découpe à l'abscisse curviligne, formules. Des tests de propriétés (fast-check) vérifient la continuité des trajectoires, l'atteinte des cibles d'IK, le volume constant du squash et l'absence de NaN.

Images dorées

Un jeu d'images de référence par style et par fonction (fusion, masque, effet, texte). Comparaison avec tolérance, dans Node (@napi-rs/canvas) et dans Chromium. Une différence volontaire se valide en régénérant la référence, avec l'image de la différence jointe à la revue.

Déterminisme et reprise

Une même scène rendue en 1, 2 et 4 morceaux donne les mêmes empreintes. Sauter à t = 17,3 s directement donne la même image que dérouler depuis 0, ressorts et cordes compris.

Génération complète

Les tests de la chaîne IA passent par un modèle bouchon, comme aujourd'hui : relecture du mouvement, correctifs, intentions, outils, rapport. Le banc d'essai tourne chaque semaine avec un vrai modèle et publie son tableau de bord.

Performance

Budget par image et par style suivi en intégration continue sur les 12 films. Une régression de plus de 15 % bloque la fusion.

Compatibilité

Migration v1 → v2 vérifiée sur tous les projets de test et sur une copie anonymisée des projets réels, avant chaque mise en production.

Ce que « fini » veut dire pour un lot

  • Format : champs facultatifs, décrits en français dans le schéma, validés, migration à jour.
  • Moteur : déterministe, avec tests unitaires et de propriétés ; aucune image changée sur les projets v1.
  • Styles : fonctionne dans les 6 styles, ou déclare pourquoi il ne s'applique pas à l'un d'eux ; images dorées.
  • IA : consignes et exemples à jour ; le contrôle signale les erreurs avec leur chemin ; test avec le modèle bouchon.
  • Mesures : critère ajouté à measure.ts quand la fonction peut mal tourner.
  • Éditeur : réglable à la main, avec un test de bout en bout.
  • Documentation : README et ARCHITECTURE à jour.
  • Performance : budget par image respecté sur le banc d'essai.
